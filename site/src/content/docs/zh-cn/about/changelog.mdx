## 1.5.0 — 2026-07-30

### 新增

- 「需要关注」面板，逐条列出失败或告警的检查及其项目、提供商和错误详情；点击任一行可跳转到该项目的详情视图。
- 项目卡片和应用详情中的 30 天历史：响应时间中位数迷你折线图和每日正常运行时间条。采集器当天未运行的日期显示为「无数据」，而不是故障。
- 成本标签页的每日花费图表，以及使用量标签页的 OpenAI token 和 GitHub Actions 运行时长趋势图。
- 提供商行上的数据过期徽章，显示该采集器的数据已有多久没有更新。
- 仪表盘头部、登录页、浏览器标签标题和落地页中的「独立开发者的状态中心」副标题。
- `npm run db:up`——一条命令搞定本地 Supabase 环境、仪表盘登录用户和被 git 忽略的 `.env.local`。另有 `db:down`、`db:reset` 和 `dev:local`。
- `npm run db:up:demo` 用覆盖所有仪表盘状态的虚构数据填充本地数据库。
- 迁移 `007_history_indexes.sql` 为 `health_checks`、`metric_snapshots` 和 `cost_snapshots` 添加时间戳索引。

### 变更

- 时间戳改用 24 小时制。
- 成本全面改为账户级：`CollectorCost` 移除了项目字段，成本标签页不再按项目过滤。
- 数据过期阈值从 24 小时改为 36 小时。

### 修复

- 仅凭资源清单行就能识别到的提供商此前会被报告为「健康」，现在在收到健康检查或指标之前显示为「未知」。

### 安全

- 升级 `vitest` 4、`eslint` 10、`astro` 7、`@astrojs/starlight` 和 `sharp` 0.35，清除所有已知漏洞告警。

## 1.0.0 — 2026-07-12

StackVitals 首次公开发布——一个自托管的、单用户运维仪表盘，为少量个人 Web 项目提供正常运行时间、部署状态、提供商状态、当月云成本和 AI/CI 使用情况的监控，同时不会从源项目中复制原始应用数据。

### 新增

- Vite + React + TypeScript 前端，从 Supabase 读取预聚合行，渲染部署状态、正常运行时间、提供商状态、域名健康、使用量汇总、采集器诊断以及当月与上月成本对比，通过详情 / 采集器 / 使用量 / 成本四个标签页展示。
- 基于统一 `ProviderAdapter` 契约的 Node 采集器管道，通过 GitHub Actions 定时运行，将追加写入的快照写回 Supabase。
- 采集器适配器：HTTP 健康检查、AWS Amplify 部署状态、AWS Cost Explorer、Supabase 项目健康、被监控应用 Supabase 聚合、Resend 域名验证、OpenAI 使用量、GitHub Actions 使用量和 Cloudflare 域名。
- 配置驱动的可选设置：适配器仅在凭证存在时激活，`projects.config.json` 解析 `${ENV_VAR}` 占位符，确保密钥不会被提交。
- 单用户访问模型，包含邮箱允许列表和 Supabase RLS。
- 带有虚构数据的演示模式和截图捕获脚本。
- CI 工作流和带有 GitHub Actions 作业摘要的定时采集器工作流。
- 自托管指南和贡献指南。
